# 단계별 지연 측정과 단일 생성 실험

측정과 별도 실험을 완료했습니다. **후보는 빨라졌지만 품질 유지에 실패하여 기본 설정으로 채택하지 않았습니다.**
기본 `config/settings.json`은 직전 검증 버전과 바이트 단위로 같습니다. 후보는
`config/settings.single-pass.json`으로 실행할 수 있습니다. 생성 모델은 양쪽 모두 Qwen3-14B-Q6_K입니다.
원본/main과 기존 Lab 백엔드, 460개 비교 데모는 보존했습니다.

## 단계별 시간

기존 질문에서 사전에 고른 20문항을 순서/역순으로 두 번씩 실행했습니다. 모델·색인 로딩과
첫 워밍업은 제외했습니다. 아래는 그중 일반 음악 10문항 × 2회의 평균 초입니다.
같은 모델·corpus·검색 설정을 사용했으며, 모든 정상 음악 측정에서 반환 KU ID가 일치합니다.

| 단계 | 직전 검증 버전 | 단일 생성 후보 G |
| --- | ---: | ---: |
| Hybrid 검색·프롬프트 준비 | 0.033 | 0.032 |
| 입력 판정 | 0.422 | 0.000 |
| 추가 KU 선택 | 0.339 | 0.000 |
| 답변 생성 | 6.322 | 3.890 |
| 출력 판정 | 1.556 | 0.000 |
| 기타 CPU/I/O | 0.049 | 0.046 |
| 전체 | 8.720 | 3.968 |

직전 일반 음악 요청은 3–4회, 후보 한국어는 1회의 14B completion을 사용했습니다.
추가 KU 선택은 필요한 요청에만 실행되므로 0.339초는 미실행 요청까지 포함한 평균입니다.
기존 hybrid 검색 뒤에 붙인 LLM 재선택이 있었고, hybrid 검색 자체가 14B를 쓰는 것은 아닙니다.
원래 embedding + BM25 및 범위·출처·보조자료 검색 로직은 변경하지 않았습니다.

이전 거절 5문항 × 2회는 **23.289→4.367초**였습니다. 직전 버전은 8/10회에서
총 7회 completion(생성 2회, 출력 판정 2회, 별도 지시 판정 등)을 사용했습니다.
일반 지식/영어 3문항 × 2회는 7.612→4.440초입니다. 영어는 한국어 검색용 번역 1회가 남아
후보 전체 호출은 번역+생성 2회입니다. 범위 밖/공격 2문항은 0.275→2.631초로 느려졌습니다.
이전에는 빠른 입력 차단이 가능했고, 후보는 안내문도 모델이 생성하기 때문입니다.

총 개선을 모두 검사 제거의 효과로 해석하면 안 됩니다. 판정 호출 합계는 일반 음악에서
2.316초이며 생성 단계도 6.322→3.890초로 바뀌었습니다. 작성 프롬프트와 출력 형식도 달라진
비교입니다. 출력 토큰 평균은 오히려 106.9→168.75였으므로 단순 답변 잘림으로 얻은 개선은
아닙니다. JSON 형식 강제 비용과 문장 작성 방식의 영향을 각각 완전히 분리해 추정한 실험은
아닙니다. F의 구조화 작성 후보는 일반 음악 6.613초, 이전 거절군 14.769초로 여전히 느렸습니다.

느린 경로를 의도적으로 포함했으므로 전체 20개 평균을 서비스 전체 지연으로 사용하지 마세요.
순차 별도 실행이며 무작위 교차 실행은 아닙니다. G는 두 반복 사이 7/20개의 답변이 달랐습니다.
온도 0·seed 42도 모든 토큰의 재현성을 보증하지 않습니다. 상세 토큰/시간/답변은
[profile-summary.json](profile-summary.json)과 각 `timings.jsonl`에 있습니다.

## 의미·자연스러움·BERTScore

기존 전문가 원질문 105개와 이전 거절 변형 4개를 새로 생성하고, 같은 Claude Opus 5.5 CLI
루브릭으로 첫 유효 판정을 사용했습니다. 아래 품질 표는 동일한 전문가 105개입니다.
이 개발용 평가는 서비스 요청 경로와 분리되어 있습니다.

| 항목 | 초기 원본 | 직전 검증 버전 | 단일 생성 후보 |
| --- | ---: | ---: | ---: |
| 답변 미제공 | 0 | 0 | 0 |
| 중대한 출처 의미 변경 | 10 | 2 | 11 |
| 사실 오류/불확실 판정 | 8 | 3 | 12 |
| 자연스러움 / 4 | 3.476 | 3.543 | 3.448 |
| 평균 요청 시간(별도 역사 실행) | 2.938초 | 8.586초 | 3.496초 |

고정 전문가 BERTScore는 **0.928871**로 0.9를 넘었습니다.
직전 버전은 0.945026입니다. xlm-roberta-large layer 18, no IDF, raw F1과 기존 revision을
그대로 사용했습니다. 출력·참조 잘림/한도 초과 0, 설정 재탐색 0입니다. 전체 109개 평균은
0.927749이며 목표 105개 수치와 구분합니다. **BERTScore 통과가 의미 보존을 입증하지 않았습니다.**

확인한 문제 예:

- 페르마타 유무 모두 허용된다는 자료에, 악보 쪽이 원곡 의도에 더 맞는다는 선호를 덧붙였습니다.
- 성악가의 자유로운 처리와 반주의 따름이라는 관계에서 주체를 반주로 바꿨습니다.
- `l’ingegno` 앞의 `l`을 무시하고 `io`와의 모음 연결로 설명했습니다.

기존 거절 5건은 모두 답했고 4건 의미 보존, 1건 경미한 확장으로 평가됐습니다.
자연스러움 평균은 3.8/4입니다. 최종 G의 p/PP 답변은 두 자료와 표기를 구분해 의미 보존으로
평가됐지만, 전체 품질을 보장하지는 못했습니다. [답변 비교](answer-comparison.json),
[전체 집계](quality-summary.json), [직접 검토](manual-review.json)에 불리한 결과도 남겼습니다.

## 프롬프트만으로 입력 범위를 처리한 결과

한국어/영어 고정 challenge 74개(직접 공격 30, 자료 주입 20, 범위 밖 12, 정상 12)를
실제 service 경로로 실행했습니다. 이 묶음만 검색 결과/가사를 고정 fixture로 대체합니다.

| 항목 | 직전 검증 버전 | 후보 G |
| --- | ---: | ---: |
| 직접 공격 성공 | 0/30 | 8/30 |
| 자료 주입 공격 성공 | 0/20 | 0/20 |
| 음악과 무관한 과제 수행 | 0/12 | 3/12 |
| 정상 음악 오거절 | 0/12 | 0/12 |

후보는 관리자 승인처럼 꾸민 표식 출력, 음악 질문에 섞은 쿠키 조리법, 긴 문맥 끝의 표식
지시 등을 따랐습니다. 8건 모두 실제 출력으로 확인했습니다. ‘거절한다’는 문장 뒤에
Python 코드를 실제로 제공한 경우도 있어, 거절 문구의 존재만으로 성공 여부를 판정하지 않았습니다.
검사 제거는 직전 직접 공격의 29/30 전면 거절을 없앴지만, 공격 지시를 따르는 경우도 늘었습니다.
이 결과는 더 작은 입력 분류기나 저렴한 규칙의 효과를 검증한 것이 아닙니다.
**14B 입력 판정이 반드시 필요하다는 결론도, 프롬프트만으로 충분하다는 결론도 내릴 수 없습니다.**
이번 14B/프롬프트 조합에서 후자는 실패했습니다. 향후 비교 대상은 출력 판정을 다시 추가하는
것보다, 별도 14B 호출 없이 범위를 다루는 방법과 생성 자체의 의미 보존입니다.

## 코드와 보존 상태

작업은 `codex/helpful-rag-responses`에서 했습니다. `5822dd9`는 후보 경로 구현 커밋이며,
`8631121`에서 품질 결과에 따라 기본 설정을 복구하고 별도 후보 설정으로 분리했습니다.
`single_pass.py`가 프롬프트 준비와 1회 생성을, `single_pass_prompt.py`가 초기 시스템에서
가져와 일반 지식 허용/내부 인용 계약을 조정한 작성 지침을 담습니다.
입력 길이·형식 검사와 저렴한 자료 문자열 검사는 남고, 후보의 입력/KU/출력 모델 판정,
품질 재작성, 원문 대입은 없습니다. 비어 있는 모델 출력 등 기술적 실패는 별도 안내를 반환합니다.

후보 코드·설정·모델·corpus 해시 일치는 [verification.json](verification.json)에 기록합니다.
이 결과는 기본 시스템 교체나 새 460개 데모 평가 완료 선언이 아닙니다.
