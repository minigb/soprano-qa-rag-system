# 조수미 KU의 적용 범위를 지키는 생성 우선순위

현재 Gemini3.8Flash 생성 프롬프트에 조수미 KU 우선 참고 지침을 추가했다. 같은 질문의 같은 대상·구간·상황·조건에 대해 실제 충돌하는 설명이 있을 때만 우선 근거로 삼는다. 다른 판본·주체·조건 또는 불명확한 적용 범위는 구분하며, 보완 정보와 선택지는 유지한다. 우선순위로 실제 악보 표기나 차이의 원인을 검증했다고 단정하지 않는다.

`single_pass_prompt.py:104`의 조건부 지침을 `single_pass.py:77`에서 붙인다. 활성화 여부는 검색 결과의 구조화된 evidence_type을 확인하며, 출처 본문이나 발화자 이름만으로 권위를 올리지 않는다. 한국어와 영어에 적용된다. 검색·KU 선택·모델·생성 설정은 유지했고, 생성 호출이나 온라인 출력 검사·답변 원문 대입은 추가하지 않았다.

## 기존 문항 비교

비교 기준은 보안 적용 전 원본이 아니라, 직전의 Gemini 결과이다. 현재 109문항 중 조수미 KU와 다른 출처가 함께 있는 8개(전문가 기반 5 + 기존 변형 3)만 새로 생성했다. 같은 질문·KU·순서·악보 문맥을 고정했다. 현재 코드로 기존 프롬프트 109개를 재구성해 확인했으며, 나머지 101개의 입력은 바이트 수준에서 동일하므로 기존 답변과 판정을 재사용했다. 기존 공격/정상 대조군의 생성 가능한 73개 입력도 변경되지 않아 재호출하지 않았다.

Claude Opus 5.5 CLI로 버전 정보를 숨긴 질문·답변·근거 패킷을 평가했다. 변경 전 답변의 첫 유효 판정을 후속 비교에도 그대로 사용했다. 새로운 답변은 첫 유효 판정을 채택했으며 불리한 판정을 다시 받아 교체하지 않았다.

| 지표 | 변경 전 | 최종 v3 |
|---|---:|---:|
| 새로 비교한 기존 문항 | 8 | 8 |
| 중대한 의미 오류 | 0 | 0 |
| 경미한 의미 오류 | 0 | 0 |
| 자연스러움 평균 /4 | 3.250 | 3.625 |
| 답변 완전성 평균 /2 | 2.000 | 2.000 |
| 오거절 | 0 | 0 |
| 전문가 105문항 BERTScore F1 | 0.950992 | 0.950608 |

최종 자연스러움 판정은 개선 3건, 동일 5건, 하락 0건이다. BERTScore는 기존 XLM-R-large / 18층 / noIDF / raw F1 및 encoder revision을 유지했다. 변경된 전문가 문항 5개를 새로 계산하고 100개의 동일 입력 점수는 재사용했다. 추가 변형 3개도 별도로 계산했으나 전문가 105개 평균에는 포함하지 않았다. 전체 답변을 평가했고 잘림이나 원문 대입은 없다.

## 경계 사례와 제한점

같은 범위의 상충 권고, 다른 공연 조건, 성악가와 반주자의 구분에 대한 가상 사례를 한국어·영어 각 3개씩 구성했다. 낮은 우선순위 자료를 먼저 배치해 순서만 따라가지 않는지도 확인했다. 이는 실제 조수미 발언이나 전문가 주석이 아닌 인공 테스트 자료이며 corpus·전문가 점수·웹 데모에 넣지 않았다.

최종 v3에서는 5개 응답을 확보했고 모두 충실성 faithful, 사실성 4/4, 완전성 2/2로 판정됐다. 다른 주체를 구분하는 영어 사례 1개는 최초 호출과 1회 기술 재시도 모두 API 504로 끝났다. 해당 사례는 미평가이며 통과로 계산하지 않는다. 앞선 v2에서는 같은 경계 사례 6개가 모두 통과했지만 그 판정을 v3에 이전하지 않았다.

첫 v1은 자연스러움 평균 3.50이었으나 표현 방법 문항에 4→3 하락이 있어 문장 연결과 문체를 보완했다. v2는 평균 3.75였으나 같은 문항에 하락이 남았다. 최종 v3에서는 관련 조언을 묶고 명백한 오탈자를 의미가 같은 표준형으로 다듬을 수 있도록 했으며, 악보 기호·숫자·인용 가사·발음 표기의 임의 수정을 금지했다. 모든 이전 출력과 판정은 보존했다. 최고 평균을 골라 문항별 답변을 섞지 않고 최종 코드의 v3 출력 8개를 모두 채택했다.

직접 대조하면 표현 방법 문항에는 원문의 비표준 표기 ‘루바도’가 최종 답변에도 남아 있다. 이전 답변에는 ‘루바토’가 있었다. Claude는 문단 연결이 개선된 최종 답변을 4점/faithful로 평가했지만, 표준 용어 교정까지 완료했다고 주장하지 않는다. 관측된 판정 하락 0건은 모든 표현이 완벽하다는 뜻이 아니다. 반복 사용한 개발 문항 8개이며 독립적인 새 검증 집합은 아니다.

관련 단위·통합 테스트 50개를 통과했다. 생성은 Gemini3.8Flash 하나만 사용했다. 예비 v1/v2 각 14회, 최종 v3 14회와 기술 재시도 1회로 총 43회 시도했고 성공 41회, 기술 실패 2회였다. 실패 2회는 같은 가상 영어 사례이며 기존 음악 문항 실패는 없다. 마지막 실행의 API 지연은 서비스 부하 영향을 받으므로 새 지침의 순수 지연 증가로 해석하지 않는다.

## 확인할 파일

- `summary.json`, `verification.json`: 최종 수치와 보존 검증.
- `comparison.md`, `v3/comparison.json`: 변경 전후 8문항의 실제 답변 전문과 판정.
- `v3/input-audit.json`: 109문항 프롬프트 및 기존 73개 대조군의 변경 범위 확인.
- `v3/bertscore/`: 고정 설정의 새 점수와 계약.
- `v3/boundaries/`: 실제 경계 사례 출력, 미평가 및 API 실패 기록.
- `snapshot/`, `v2/snapshot/`, `v3/snapshot/`: 각 생성 지침.
- `v3/combined/`: 변경된 8개와 동일 입력의 기존 101개를 결합한 데모용 결과.

작업 브랜치는 `codex/helpful-rag-responses`이다. 원본/main과 이전 평가 출력은 보존했다. 데모의 새 기본 버전은 `gemini-priority-20261107`이고 변경 전 Gemini와 과거 460문항 버전도 유지한다. ‘이번 변경 문항’ 필터로 8개를 확인할 수 있다. 데모 서버는 사용자가 직접 시작한다.

이전 완료된 생성 스크립트는 다시 실행하지 않는다. 후속 실험은 새 버전 디렉터리에 첫 응답·실패를 보존한다. 온라인 답변의 출력 평가, Discord 알림 또는 usage-reset 중지 조건을 추가하지 않는다.
